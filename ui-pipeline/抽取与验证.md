## 管线结构

项目识别 → 界面契约 → 视觉 token → 框架接入 → 状态与阅读行为 → 验收与交付。

| 部分 | 复用内容 |
|---|---|
| [技能入口](workbench-ui-pipeline/SKILL.md) | 识别项目、选组织模式、实施、验证和交付 |
| [视觉规范](workbench-ui-pipeline/references/visual-system.md) | 深浅主题、文字与数据字体、密度、间距、控件状态、图标与文案 |
| [组织与状态](workbench-ui-pipeline/references/layout-and-state.md) | 六层工作区、三类布局、来源绑定、稳定身份、查找与返回 |
| [项目契约](workbench-ui-pipeline/assets/project-contract.json) | 主任务、操作、布局、状态、语言和验证范围 |
| [生成器](workbench-ui-pipeline/scripts/build.py) | 同源生成 CSS、Qt 调色板与 QSS、离线 Web 样板、Qt 样板 |
| [接入说明](workbench-ui-pipeline/references/adapters.md) | Web／Qt／其他框架的映射与边界 |
| [验收方法](workbench-ui-pipeline/references/verification.md) | 窗口、状态、键盘、更新、性能与证据记录 |

品牌、采集／协议分析、EtherScope 字段和服务留在原项目。具体业务数据和动作需要在目标项目连接；生成的样板使用演示数据。Qt 样板采用原生外框，无边框系统行为由目标平台实施和验收。
