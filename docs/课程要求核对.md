# 题目 A 协议分析器设计：要求核对

核对对象为 EtherScope v2.3.0 本地预览源码。题目要求以本次用户提供的六项设计要求和五项评分依据为准。

## 六项设计要求

| 要求 | 当前实现 | 核对结论 |
|---|---|---|
| Windows/Linux 运行并有界面 | Qt Widgets 图形界面；Windows Npcap 实时捕获；Linux CI 仅构建核心 | Windows 路径具备；Linux 完整图形抓包路径尚未完成 |
| 实时捕捉 Ethernet 数据帧 | 后台捕获线程调用 Npcap，检查 DLT_EN10MB，队列向界面分批交付 | Windows 已实现，本轮物理接口验收链路类型为 Ethernet |
| 解析 Ethernet 各字段 | 源 MAC、目的 MAC、类型／长度、数据范围、捕获和原始长度，支持单层 VLAN | 已实现 |
| 解析 IP 首部各字段 | IPv4 版本、首部长度、DSCP、ECN、总长度、标识、标志、片偏移、TTL、协议、检验和、源／目的地址和选项；另支持 IPv6 | 已实现 |
| 基于 MAC 和 IP 过滤 | MAC、IPv4、IPv6，源／目的／任一方向；组合显示过滤；非法输入保留已生效条件 | 已实现 |
| 四种 ICMP | Type 8 回显请求、0 回显应答、11 时间超过、3 目的地址不可达；显示 Code、检验和、序列等字段和引用首部 | 已实现 |

若按 Windows 作为课程运行平台，六项能力均有实现。若要求 Windows 和 Linux 都能完整实时抓包，第 1、2 项仍需补齐 Linux libpcap 后端并进行 Linux 图形界面与真实网卡验收。

Linux 缺口的直接依据：`src/capture/capture.cpp` 的非 Windows 分支会返回“实时抓包当前仅支持 Windows Npcap”；`.github/workflows/ci.yml` 的 Linux 作业使用 `ETHERSCOPE_BUILD_GUI=OFF`。当前机器无已安装 WSL Linux 发行版，本轮不把 Linux 核心测试记作 Linux 桌面验收。

Ethernet 字段按网卡实际交付的捕获内容显示。前导码和 SFD 通常由网卡处理；当前捕获格式未提供 FCS 时，字段显示未捕获。IPv4 分片显示首部及片偏移，本版本没有 IP 分片重组。

## 代码与验证入口

| 内容 | 源码 | 回归入口 |
|---|---|---|
| 图形界面、状态与过滤 | `src/ui/main_window*.cpp`、`src/ui/packet_model.cpp` | `tests/ui_tests.cpp`、`tests/workspace_tests.cpp` |
| 捕获、停止、队列预算 | `src/capture/capture.cpp` | `tests/capture_probe.cpp`、`tests/native_acceptance.cpp` |
| Ethernet | `src/core/decode/link.inc` | `tests/core_tests.cpp` 的 `protocols` |
| IPv4 首部与选项 | `src/core/decode/ipv4.inc`、`ipv4_options.inc` | `tests/core_tests.cpp` |
| 地址过滤 | `src/core/filter.cpp` | `tests/core_tests.cpp`、`courseEthernetIpIcmpAndFilters` |

四种 ICMP 的界面核对使用构造 Ethernet 数据，覆盖字段展示和筛选。真实物理网卡短时捕获及本机 HTTP 回环属于另一组验收记录。

## 课堂演示路径

1. Windows 安装 Npcap，启动预览，选择有地址的物理网卡。开始捕获并确认 Ethernet II 字段组。
2. 选中 IPv4 报文，展开 Ethernet II 和 IPv4，查看字段与字节高亮。
3. 展开地址筛选，输入当前报文的源 MAC 和 IP，应用；改为不匹配的地址，确认结果为空；清除恢复。
4. 打开 `samples/synthetic-protocols.pcap`，依次查看四种 ICMP。Type 11 查看超时原因；Type 3 查看不可达 Code 与引用首部。
5. 展示非法地址提示、查找、定位返回，以及停止、保存和重新打开文件。
