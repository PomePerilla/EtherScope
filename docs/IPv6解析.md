# IPv6 解析

## 使用

选择联网的普通Wi-Fi或以太网网卡，清除旧过滤并开始捕获。协议选择“IPv6”可显示所有已解析的IPv6包，包括其上的TCP、UDP和ICMPv6；选择“ICMPv6”仅显示ICMPv6。IP框支持IPv4或IPv6完整地址以及源、目的、任一方向选择，与MAC条件取交集。

IPv6地址支持压缩写法、大小写和IPv4嵌入尾部，例如`2001:0DB8::1`、`::ffff:192.0.2.1`；按地址字节比较。显示和已生效设置使用压缩的小写形式。输入不含方括号、`%接口`或CIDR前缀；链路本地地址过滤只填`fe80::…`。Windows命令行向链路本地地址发ping时可能需要`%接口编号`，这与抓包过滤框的输入格式不同。

列表显示IPv6源/目的地址；点击报文展开“IPv6”与扩展/上层首部，可查看字段并定位原始字节。实时抓包与PCAP导入使用同一解析器，保存保留原始字节，包含显示过滤隐藏的记录。有效IPv6过滤会随设置恢复；非法草稿不覆盖生效条件。

打开`samples/synthetic-ipv6.pcap`可离线演示21个构造报文；该文件不包含真实用户流量。

## 支持范围

| 部分 | 本版解析内容 |
|---|---|
| IPv6基本首部 | 版本、流量类别、DSCP/ECN、流标签、有效载荷长度、下一首部、跳数限制、128位源/目的地址 |
| 扩展首部 | 按出现顺序遍历Hop-by-Hop、Routing、Destination Options、Fragment、AH；展示长度、下一首部、选项范围、分片偏移/标识/M位、路由类型/剩余段数、AH SPI/序列号 |
| TCP/UDP | 复用现有基本首部解析，扩展首部之后定位到正确偏移 |
| ICMPv6 | 公共首部；回显标识符/序号；目的不可达、数据包过大、时间超过、参数问题及IPv6引用；不递归解析引用报文 |
| 邻居发现 | 路由器请求/通告、邻居请求/通告、重定向；目标地址、通告标志、寿命/计时器；链路地址、前缀和MTU选项 |
| VLAN | 单层802.1Q承载IPv6，字段偏移自动调整 |

首部和TLV选项必须位于IPv6声明的有效载荷及已捕获字节范围内，不借用Ethernet填充补足首部。异常长度、零长度邻居发现选项及截断数据会报告错误。扩展链最多解析32个，超出后停止并报告；Hop-by-Hop若不紧随基本首部、重复分片首部均拒绝继续遍历。

非首片不解析上层首部；首片仅展示已捕获且足够完整的上层字段，不做分片重组。ESP仅展示SPI/序列号并标注加密，未知下一首部保留原始字节。Jumbo Payload、IPv6隧道递归、所有路由类型的专有字段、MLD细项、应用层协议、密码学认证和校验和验证不在本次范围内。本程序是抓包字段分析器，不是完整IPv6协议合规检查器。

## 验证

- 当前版本回归与性能见 `验证记录.md`、`性能结果.md`。
- Wireshark/tshark 4.6.9 核对 21 个 IPv6 构造包，430 个已解析字段值一致。核对关闭 IP 重组。
- 本机真实测试：2026年10月20日15:40，Npcap在Wi-Fi接口接收6秒，共224包。向IPv6链路本地网关发送带唯一标记的4次真实请求，捕获4请求和4应答（Type 128/129），队列丢弃和驱动本次报告丢包均为0，停止完成15毫秒。真实样本另经tshark核对8包、168字段。
- 构造样本位于源码包 `samples`。本机真实地址、PCAP 及 Ping 记录位于本地 `output/live-ipv6-test-20261020`，不加入发行包。

## 实现依据

按[RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html)读取IPv6基本与扩展首部，按[RFC 4443](https://www.rfc-editor.org/rfc/rfc4443.html)读取ICMPv6，邻居发现字段参考[RFC 4861](https://www.rfc-editor.org/rfc/rfc4861.html)，地址显示参考[RFC 5952](https://www.rfc-editor.org/rfc/rfc5952.html)。这些参考不表示本程序实现上述标准的全部功能。
